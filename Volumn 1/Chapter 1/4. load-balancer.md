# Load Balancer (Chapter 1)

> Note: বইয়ের figure গুলো (Figure 1-4, 1-6) আমার কাছে ছিল না, তাই diagram গুলো বইয়ের text অনুযায়ী আমি নিজে এঁকেছি। বইয়ের বাইরের উদাহরণ ও মন্তব্য "বাড়তি ব্যাখ্যা" লিখে আলাদা করা আছে।

---

## আগের design এ সমস্যা কী ছিল?

Topic 3 এর শেষে আমরা দেখেছি, user সরাসরি web server এ connect করত। এতে দুটো সমস্যা:

1. Web server **offline** হলে user কেউ website এ ঢুকতে পারে না।
2. অনেক user একসাথে এলে server এর **load limit** পার হয়ে যায়। তখন response ধীর হয় বা connection ই হয় না।

বইয়ের মতে এই সমস্যাগুলো সামলানোর **সবচেয়ে ভালো কৌশল** হলো load balancer।

---

## Load Balancer কী?

Load balancer incoming traffic কে একটা **load-balanced set** এ থাকা web server গুলোর মধ্যে **সমানভাবে ভাগ করে** দেয়।

### Figure 1-4 (নিজের আঁকা)

```
                    +-----------------+
   Users ---------> |  Load Balancer  |   <-- Public IP
                    +-----------------+
                       |           |
                 Private IP     Private IP
                       |           |
                       v           v
                 +----------+ +----------+
                 | Server 1 | | Server 2 |
                 +----------+ +----------+
```

---

## কীভাবে কাজ করে?

### 1. Public IP আর Private IP

- User শুধু load balancer এর **public IP** এর সাথে connect করে।
- এই setup এ web server গুলোতে client সরাসরি পৌঁছাতে পারে না।
- **Security ভালো করার জন্য** load balancer আর web server এর মধ্যে যোগাযোগ হয় **private IP** দিয়ে।

**Private IP কী?** এটা এমন IP address যেটা শুধু **একই network এর server গুলোর মধ্যে** পৌঁছানো যায়। Internet থেকে এটাতে যাওয়া যায় না।

### বাড়তি ব্যাখ্যা (বাড়ির উদাহরণ)

একটা অফিসের কথা ভাবুন:
- **Reception desk** = load balancer (বাইরের লোক শুধু এখানেই আসে)
- **ভেতরের কর্মীরা** = web server (বাইরের লোক সরাসরি তাদের কাছে যেতে পারে না)
- Reception ঠিক করে দেয় কোন কর্মী কাকে সামলাবে।

## যে সমস্যাগুলোর সমাধান হলো

Figure 1-4 এ load balancer ও দ্বিতীয় web server যোগ করার পর বইয়ের মতে **"no failover" সমস্যা মিটল আর web tier এর availability বাড়ল।** বিস্তারিত:

### সমাধান 1: একটা server বন্ধ হলে

```
আগে (স্বাভাবিক):                  Server 1 বন্ধ হলে:

  LB                                LB
  /  \                                \
 v    v                                v
S1    S2                        S1(X)  S2   <-- সব traffic এখানে
```

- Server 1 offline হলে **সব traffic Server 2 তে চলে যায়।** তাই website বন্ধ হয় না।
- এরপর pool এ একটা **নতুন healthy server যোগ** করা হয়, যাতে load আবার ভাগ হয়ে যায়।

### সমাধান 2: Traffic হঠাৎ বাড়লে

```
দুটো server যথেষ্ট না হলে:

        LB
      / | | \
     v  v v  v
    S1 S2 S3 S4   <-- নতুন server যোগ হলো
```

- Web server pool এ **আরো server যোগ** করলেই হয়।
- Load balancer **নিজে থেকেই** নতুন server গুলোতে request পাঠানো শুরু করে। আলাদা কোনো কনফিগ বদলাতে হয় না।
- বইয়ের ভাষায় load balancer এই সমস্যা "gracefully" সামলাতে পারে।

## Request flow (পূর্ণ চিত্র)

বইয়ের পরের অংশে load balancer ও database replication যোগ হওয়ার পর flow এমন (Figure 1-6 এর ধারণা):

```
 User
  |
  | (1) DNS থেকে load balancer এর IP আনে
  v
 Load Balancer
  |
  | (2) request যায় Server 1 বা Server 2 তে
  v
 Web Server
  |
  | (3) read হলে  --> Slave database থেকে
  | (4) write হলে --> Master database এ
  v
 Database
```

এই database অংশটা আমরা **Topic 5 (Database Replication)** এ বুঝব।

---

## এখনো কী বাকি আছে?

Web tier এখন ঠিক। কিন্তু **data tier এ এখনো একটাই database**। সেটা বন্ধ হলে failover বা redundancy নেই। এর সমাধান **database replication**, যা পরের topic।

---

## আপনার POS এর সাথে মিলিয়ে (বাড়তি ব্যাখ্যা)

- একটা Express server দিয়ে শুরু করলে load balancer লাগে না।
- যখন দ্বিতীয় Express server যোগ করবেন (availability বা বেশি load এর জন্য), তখন তার সামনে load balancer বসাবেন।
- Cloud এ এটা সাধারণত managed service হিসেবে পাওয়া যায় (যেমন AWS এর load balancer)। নিজে বানানোর দরকার হয় না।
- মনে রাখবেন: load balancer ও নিজে একটা single point of failure হতে পারে। বইয়ের Chapter 15 এ বলা আছে, বাস্তবে একটা secondary load balancer থাকে যা heartbeat দিয়ে primary কে নজরে রাখে এবং সেটা fail করলে কাজ নিয়ে নেয়।

## Interview তে কীভাবে বলবেন?

> "Web server গুলোর সামনে একটা load balancer বসাব। User শুধু load balancer এর public IP দেখবে, আর server গুলো private IP তে থাকবে, যাতে security ভালো থাকে। একটা server বন্ধ হলে traffic বাকি server এ চলে যাবে, আর traffic বাড়লে শুধু server যোগ করলেই হবে।"

## মনে রাখার পয়েন্ট

| বিষয় | সারকথা |
|---|---|
| Load balancer এর কাজ | Traffic কে web server গুলোর মধ্যে সমানভাবে ভাগ করা |
| Public IP | User শুধু এটাই দেখে, সরাসরি web server এ যেতে পারে না |
| Private IP | Server গুলোর মধ্যে যোগাযোগ, internet থেকে পৌঁছানো যায় না, নিরাপদ |
| Server বন্ধ হলে | Traffic বাকি server এ যায়, নতুন server যোগ করা হয় |
| Traffic বাড়লে | Pool এ server যোগ করলেই load balancer স্বয়ংক্রিয়ভাবে ব্যবহার করে |
| বাকি সমস্যা | Database এখনো একটা, সমাধান replication |

## Self-check questions

2. Web server গুলোর জন্য কেন private IP ব্যবহার করা হয়? Private IP বলতে কী বোঝায়?
3. Server 1 বন্ধ হয়ে গেলে কী ঘটে?
4. Traffic হঠাৎ অনেক বেড়ে গেলে load balancer থাকলে কী করতে হয়?
5. Load balancer থাকার পরেও system এ কোন দুর্বল জায়গা থেকে যায়?
