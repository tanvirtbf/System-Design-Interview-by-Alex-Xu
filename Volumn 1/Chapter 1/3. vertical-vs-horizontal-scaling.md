# Vertical Scaling vs Horizontal Scaling (Chapter 1)

> Note: বইয়ের figure গুলো আমার কাছে ছিল না, তাই diagram গুলো বইয়ের text অনুযায়ী আমি নিজে এঁকেছি। বইয়ের বাইরের উদাহরণ ও মন্তব্য "বাড়তি ব্যাখ্যা" লিখে আলাদা করা আছে।

---

## ভূমিকা: scaling কেন দরকার?

User বাড়লে একটা server আর সব request সামলাতে পারে না। তখন system কে "বড়" করতে হয়, এটাকেই বলে **scaling**। বড় করার দুটো পথ আছে:

1. **Vertical scaling** (scale up)
2. **Horizontal scaling** (scale out)

---

## 1. Vertical Scaling (Scale Up)

**সংজ্ঞা:** আগের server এই আরো শক্তি (CPU, RAM ইত্যাদি) যোগ করা।

```
  আগে                         পরে
+-----------+             +----------------+
|  Server   |   ----->    |    Server      |
|  2 CPU    |             |    16 CPU      |
|  4 GB RAM |             |    64 GB RAM   |
+-----------+             +----------------+
   (একই একটা machine, শুধু শক্তিশালী)
```

### সুবিধা
- **Simplicity** (সহজ)। বইয়ের মতে এটাই এর প্রধান সুবিধা।
- Code বা architecture তেমন বদলাতে হয় না।
- Traffic কম থাকলে এটা দারুণ বিকল্প।

### সীমাবদ্ধতা (বইয়ের দুটো)

1. **Hard limit আছে।** একটা server এ অসীম CPU আর memory যোগ করা অসম্ভব।
2. **Failover ও redundancy নেই।** একটা server বন্ধ হলে website বা app পুরোপুরি বন্ধ হয়ে যায়।

### বাড়তি ব্যাখ্যা
- Server যত শক্তিশালী হয়, দাম অনেক দ্রুত বাড়ে। (বইয়ের পরের অংশে database এর ক্ষেত্রে বলা আছে: শক্তিশালী server অনেক বেশি দামি।)

---

## 2. Horizontal Scaling (Scale Out)

**সংজ্ঞা:** নিজের resource pool এ আরো server যোগ করা।

```
  আগে                         পরে
+-----------+        +-----------+ +-----------+ +-----------+
|  Server   | -----> | Server 1  | | Server 2  | | Server 3  |
+-----------+        +-----------+ +-----------+ +-----------+
                      (একাধিক সাধারণ machine একসাথে কাজ করে)
```

### সুবিধা
- বইয়ের মতে **বড় scale এর application এর জন্য এটাই বেশি কাম্য**, কারণ vertical scaling এর সীমাবদ্ধতাগুলো এখানে নেই।
- Server যোগ করার কোনো কঠিন সীমা নেই।
- একটা server বন্ধ হলে বাকিগুলো কাজ চালিয়ে যেতে পারে (এটার জন্য load balancer লাগে, যা Topic 4)।

### বাড়তি ব্যাখ্যা
- Horizontal scaling এ system জটিল হয়। একাধিক server এর মধ্যে request ভাগ করা, state ঠিক রাখা, data মেলানো, এগুলো নতুন চ্যালেঞ্জ। বইয়ের পরের topic গুলো (load balancer, stateless web tier, replication) ঠিক এই চ্যালেঞ্জগুলোই সামলায়।

---

## পাশাপাশি তুলনা

| বিষয় | Vertical (Scale Up) | Horizontal (Scale Out) |
|---|---|---|
| কী করা হয় | একই server এ CPU/RAM বাড়ানো | আরো server যোগ করা |
| Simplicity | খুব সহজ | তুলনামূলক জটিল |
| সীমা | Hard limit আছে | সীমা অনেক বেশি |
| Failover/redundancy | নেই | আছে (load balancer সহ) |
| কখন ভালো | traffic কম হলে | বড় scale এর application এ |

---

## এই সীমাবদ্ধতা থেকে নতুন কোন সমস্যা আসে?

আগের design এ user সরাসরি web server এ connect করে। এতে দুটো সমস্যা:

1. **Server offline হলে** user কেউ website এ ঢুকতে পারে না।
2. **অনেক user একসাথে এলে** server এর load limit পার হয়ে যায়। তখন response ধীর হয় বা connection ই হয় না।

বইয়ের সমাধান: **Load balancer**। এটা পরের topic (Topic 4)।

## আপনার POS এর সাথে মিলিয়ে (বাড়তি ব্যাখ্যা)

আমরা আগে হিসাব করেছিলাম একটা সাধারণ VPS এ কয়েক হাজার user চলে যাবে।

- শুরুতে ছোট VPS দিয়ে চালানো, তারপর দরকার হলে $20 থেকে $100 এর বড় server এ যাওয়া হলো **vertical scaling**।
- পরে User আরো বাড়লে বা server বন্ধ হওয়ার ঝুঁকি কমাতে দ্বিতীয় server যোগ করে load balancer বসানো হলো **horizontal scaling**।

ছোট শুরুতে vertical scaling ই সবচেয়ে সহজ ও সস্তা। Horizontal এ যাবেন তখন, যখন availability বা বড় scale এর দরকার হবে। না হলে আগে থেকেই জটিল করলে সেটা over-engineering।

## Interview তে কীভাবে বলবেন?

> "শুরুতে vertical scaling দিয়ে সহজে চালাব। কিন্তু এর hard limit আছে আর failover নেই। তাই বড় scale এ horizontal scaling এ যাব, আর load balancer বসাব।"

## মনে রাখার পয়েন্ট

| বিষয় | সারকথা |
|---|---|
| Vertical scaling | একই server এ CPU/RAM বাড়ানো। সহজ, কিন্তু hard limit আর failover নেই |
| Horizontal scaling | আরো server যোগ করা। বড় scale এ কাম্য |
| Single server এর ঝুঁকি | বন্ধ হলে সব বন্ধ, আর অতিরিক্ত load এ ধীর বা fail |
| সমাধান | Load balancer (Topic 4) |

## Self-check questions

1. Vertical scaling আর horizontal scaling এর মধ্যে মূল পার্থক্য কী?
2. Vertical scaling এর দুটো সীমাবদ্ধতা কী কী?
3. কেন বড় scale এর application এর জন্য horizontal scaling বেশি পছন্দ করা হয়?
4. Web server সরাসরি user এর সাথে connect থাকলে কোন দুটো সমস্যা হয়?
5. আপনার POS এ কখন vertical scaling যথেষ্ট, আর কখন horizontal scaling এ যাবেন?
